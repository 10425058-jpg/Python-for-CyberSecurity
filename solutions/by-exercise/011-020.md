## Exercise 011 — List versus set membership

**Reference solution:**

```python
items = ["a","b","a"]
unique = set(items)
assert "a" in unique
assert len(unique) == 2
assert len(items) == 3
```

**Why the answer works:** Set membership is expected O(1), list membership O(n).

**Boundary/negative check:** Try a non-hashable list as a set member; expect TypeError.

**Security interpretation:** Unbounded set cardinality is a memory DoS risk.

**What to submit:** your own reimplementation, one positive test, one negative test and a paragraph explaining the invariant. Do not claim production readiness.

## Exercise 012 — Counter frequency

**Reference solution:**

```python
from collections import Counter
c = Counter(["fail","ok","fail"])
assert c["fail"] == 2 and c["ok"] == 1
```

**Why the answer works:** Counter builds an actor/event histogram without retaining raw event list.

**Boundary/negative check:** Test empty stream: Counter() has no keys.

**Security interpretation:** Counts alone do not prove an event was hostile.

## Exercise 013 — Dictionary canonicalization

**Reference solution:**

```python
raw = {"Alice":2, "alice":1}
canonical = {}
for name,count in raw.items():
    key = name.casefold()
    canonical[key] = canonical.get(key,0) + count
assert canonical == {"alice":3}
```

**Why the answer works:** Normalize only if source identity semantics permit case folding.

**Boundary/negative check:** Test two intentionally distinct IDs: merging would be incorrect.

**Security interpretation:** Preserve raw identities and document canonicalization.

**What to submit:** your own reimplementation, one positive test, one negative test and a paragraph explaining the invariant. Do not claim production readiness.

## Exercise 015 — Bounded deque

**Reference solution:**

```python
from collections import deque
recent = deque(maxlen=2)
for i in (1,2,3):
    recent.append(i)
assert list(recent) == [2,3]
```

**Why the answer works:** The oldest element is evicted automatically after maxlen.

**Boundary/negative check:** Test zero events and one event.

**Security interpretation:** A bounded preview queue must not replace evidence retention.

**What to submit:** your own reimplementation, one positive test, one negative test and a paragraph explaining the invariant. Do not claim production readiness.

## Exercise 016 — Sliding time window

**Reference solution:**

```python
from collections import deque
q = deque()
for second in (0,30,60,61):
    while q and second-q[0] > 60:
        q.popleft()
    q.append(second)
assert list(q) == [30,60,61]
```

**Why the answer works:** Inclusive boundary keeps t=0 at t=60 but expires it at t=61.

**Boundary/negative check:** Test out-of-order times separately; this snippet assumes sorted records.

**Security interpretation:** Define event time vs ingest time before deploying burst rules.

**What to submit:** your own reimplementation, one positive test, one negative test and a paragraph explaining the invariant. Do not claim production readiness.

## Exercise 017 — Heap-based top-K

**Reference solution:**

```python
from heapq import nlargest
counts = {"a":10,"b":2,"c":8}
assert nlargest(2, counts.items(), key=lambda pair:pair[1]) == [("a",10),("c",8)]
```

**Why the answer works:** Use a bounded heap to select K from already aggregated counts.

**Boundary/negative check:** Test ties and define deterministic tie-break semantics.

**Security interpretation:** Top-K results may hide low-frequency critical outliers.

**What to submit:** your own reimplementation, one positive test, one negative test and a paragraph explaining the invariant. Do not claim production readiness.

## Exercise 018 — Stable sorting

**Reference solution:**

```python

result = sorted(items, key=lambda e:e[0])
```

## Exercise 019 — Duplicate detection

**Reference solution:**

```python
seen = set()
records = [("lab","id-1"),("lab","id-1"),("other","id-1")]
kept = []
for record in records:
    if record not in seen:
        kept.append(record)
        seen.add(record)
assert len(kept) == 2
```

**Why the answer works:** Use a stable tuple of source and event ID.

**Boundary/negative check:** Test empty event ID and require schema validation before this code.

**Security interpretation:** Incorrect dedup can erase distinct evidence.

**What to submit:** your own reimplementation, one positive test, one negative test and a paragraph explaining the invariant. Do not claim production readiness.

## Exercise 020 — Complexity measurement

**Reference solution:**

```python
from time import perf_counter
data = list(range(1000))
start = perf_counter()
value = sum(data)
elapsed = perf_counter() - start
assert value == 499500 and elapsed >= 0
```

**Why the answer works:** Measure elapsed time; benchmark multiple input sizes to infer growth.

**Boundary/negative check:** Compare N=1000 vs 10000 but do not assert a fragile exact speed ratio.

**Security interpretation:** A fast algorithm can still exhaust memory with attacker-controlled keys.

**What to submit:** your own reimplementation, one positive test, one negative test and a paragraph explaining the invariant. Do not claim production readiness.
