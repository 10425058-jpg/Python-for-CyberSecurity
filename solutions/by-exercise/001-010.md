## Exercise 001 — Object identity versus value equality

**Reference solution:**

```python
left = [1]
alias = left
copy = left.copy()
alias.append(2)
assert left == [1,2] and alias is left
assert copy == [1] and copy is not left
```

**Why the answer works:** Both names refer to one mutable list; .copy creates a new outer list.

**Boundary/negative check:** Nested lists still alias under shallow copy.

**Security interpretation:** Shared mutable state can contaminate event processing.

**What to submit:** your own reimplementation, one positive test, one negative test and a paragraph explaining the invariant. Do not claim production readiness.

## Exercise 003 — Boolean-versus-integer boundaries

**Reference solution:**

```python
def strict_count(n):
    if type(n) is not int or not 0 <= n <= 20:
        raise ValueError("count")
    return n
assert strict_count(3) == 3
try:
    strict_count(True)
except ValueError:
    pass
else:
    raise AssertionError("bool accepted")
```

**Why the answer works:** True compares equal to 1, and isinstance(True,int) returns True.

**Boundary/negative check:** Test -1, 21, 3.0, '3', None.

**Security interpretation:** Schema validation must check exact numeric types when booleans are distinct.

**What to submit:** your own reimplementation, one positive test, one negative test and a paragraph explaining the invariant. Do not claim production readiness.

## Exercise 004 — Validated command-line input

**Reference solution:**

```python
import argparse
def parse_args(argv):
    parser = argparse.ArgumentParser()
    parser.add_argument("--port", type=int, required=True)
    args = parser.parse_args(argv)
    if not 1 <= args.port <= 65535:
        parser.error("port out of range")
    return args.port
assert parse_args(["--port","443"]) == 443
```

**Why the answer works:** argparse converts text; explicit policy validates its range.

**Boundary/negative check:** Try '--port 0' and '--port abc'; argparse raises SystemExit.

**Security interpretation:** A syntactically valid CLI argument may still be prohibited.

**What to submit:** your own reimplementation, one positive test, one negative test and a paragraph explaining the invariant. Do not claim production readiness.

## Exercise 005 — Control-flow branches

**Reference solution:**

```python
def decide(enabled, blocked):
    if type(enabled) is not bool or type(blocked) is not bool:
        raise ValueError("policy schema")
    if not enabled:
        return "deny-disabled"
    if blocked:
        return "deny-blocked"
    return "allow"
assert decide(True,False) == "allow"
assert decide(True,True) == "deny-blocked"
```

**Why the answer works:** Policy defaults are explicit, not based on falsy coercion.

**Boundary/negative check:** Test enabled=None, blocked=0 and disabled True.

**Security interpretation:** Malformed security policy should fail closed.

**What to submit:** your own reimplementation, one positive test, one negative test and a paragraph explaining the invariant. Do not claim production readiness.

## Exercise 006 — Default mutable arguments

**Reference solution:**

```python
def add(actor, actors=None):
    if actors is None:
        actors = []
    actors.append(actor)
    return actors
```

**Why the answer works:** A new list is allocated per call; a default [] would be shared.

**Boundary/negative check:** Test repeated independent calls.

## Exercise 009 — Exact event schemas

**Reference solution:**

```python
def validate(obj):
    if type(obj) is not dict or set(obj) != {"actor","action"}:
        raise ValueError("schema")
    if type(obj["actor"]) is not str or not obj["actor"]:
        raise ValueError("actor")
    if obj["action"] not in {"success","failure"}:
        raise ValueError("action")
    return obj
assert validate({"actor":"a","action":"failure"})["actor"] == "a"
```

**Why the answer works:** Reject extra/missing keys and unknown actions before using event fields.

**Boundary/negative check:** Test actor=None, action=9, missing action and extra password field.

**Security interpretation:** Invalid events should not silently influence alert counts.

## Exercise 010 — Readable exception handling

**Reference solution:**

```python
import json
def parse_object(raw):
    try:
        value = json.loads(raw)
    except json.JSONDecodeError as exc:
        raise ValueError("malformed JSON") from exc
    if type(value) is not dict:
        raise ValueError("object required")
    return value
assert parse_object('{"ok":true}') == {"ok": True}
```

**Why the answer works:** Translate expected parser failures while keeping the exception cause.

**Boundary/negative check:** Test malformed '{' and valid top-level [] .

**Security interpretation:** except Exception: return [] may create a false security all-clear.

**What to submit:** your own reimplementation, one positive test, one negative test and a paragraph explaining the invariant. Do not claim production readiness.
