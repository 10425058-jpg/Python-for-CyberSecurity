# Workshop 01 — Build and break a *safe toy* binary protocol

**Duration:** 2–3 hours · **Environment:** Python 3.11+ · **Network:** none · **Dependency:** standard library only.

## Problem statement
You receive a file containing messages in an invented format. You must parse it safely. A buggy parser might misinterpret byte order, accept unsupported versions, allocate unreasonable buffers, or silently ignore trailing data. Your job is to implement a parser and prove it rejects malformed inputs.

## Safety
This exercise uses an invented format and locally generated bytes. It is **not** exploit code and does not transmit packets or execute unknown files.

## 1. The wire contract

```text
+--------+-------+------+--------+--------------+
| magic  | ver   | type | length | JSON payload |
| 2 byte | 1 byte|1 byte|2 bytes | N bytes      |
+--------+-------+------+--------+--------------+

magic=b"SC", version=1, type=1 or 2,
length = big-endian unsigned 16-bit,
N <= 1024, payload = UTF-8 JSON object.
```

For a payload `{"ok":true}`, bytes are encoded as UTF-8 and prepended by a six-byte header. Network byte order is big-endian; `!2sBBH` in `struct` expresses the wire layout.

## 2. Run the reference implementation
From the repository root:
```bash
python -m examples.strict_frame
python -m unittest tests.test_deep_examples.StrictFrameTests -v
```

**Expected shape (hex value depends on JSON separators but is deterministic):**
```text
hex: 5343010100277b...
decoded: {'version': 1, 'message_type': 1,
          'payload': {'source': 'local-lab', 'status': 'ok'}}
```

The hex example is truncated with ellipsis; **don't** use it as exact expected bytes. Instead check:
- The first two bytes are `53 43`.
- The third byte is `01`.
- The fourth byte is the message type.
- The next two bytes equal the number of UTF-8 JSON payload bytes.
- The decoder returns the original Python dict.

## 3. Read the code line-by-line

Open [examples/strict_frame.py](../examples/strict_frame.py).

- `HEADER_SIZE = struct.calcsize("!2sBBH")` should equal 6.
- `encode_frame` checks the message type before packing.
- `json.dumps(..., allow_nan=False)` rejects NaN/Infinity when encoding.
- `encode("utf-8")` produces bytes, not code-point count.
- `MAX_PAYLOAD` caps size before building the frame.
- `decode_frame` checks for at least six bytes before unpacking.
- Unknown version/type/magic is rejected instead of guessed.
- Actual length must equal declared length (trailing bytes are not ignored).
- Strict UTF-8 decoding precedes JSON parsing.
- `object_pairs_hook` prevents duplicate JSON keys from silently overwriting values.
- A top-level array is rejected because the contract requires an object.

### Why duplicate keys matter
Standard JSON dictionaries in many parsers keep the last of two identical keys. If one component authorizes based on the first key and another reads the last, systems can disagree about the meaning of a message. A defensive parser can reject ambiguity.

## 4. Deliberately create malformed input

Work in a Python REPL:
```python
from examples.strict_frame import encode_frame, decode_frame

valid = encode_frame(1, {"event": "synthetic"})
bad_magic = b"XX" + valid[2:]
bad_truncated = valid[:-1]
bad_extra = valid + b"\x00"

for item in [bad_magic, bad_truncated, bad_extra]:
    try:
        decode_frame(item)
    except ValueError as exc:
        print(type(exc).__name__, str(exc))
    else:
        raise AssertionError("bad frame accepted")
```

**Expected:** three failures: invalid magic, length mismatch, length mismatch. No segfault, no silent success.

### What the tests prove / don't prove
They demonstrate properties of the toy parser under checked inputs. They do not prove safety against every possible input, DoS in the JSON library or correctness of a real binary protocol.

## 5. Trace a frame manually

Suppose a header bytestring is `53 43 01 02 00 0b`. Decode:
- Magic: `53 43` = "SC".
- Version: `01` = 1.
- Type: `02` = 2.
- Length: `00 0b` = 11 decimal.
- Now read **exactly** 11 payload bytes; if there are 10 or 12, reject.

The payload must be valid UTF-8 JSON representing an object. A header being well formed is not enough.

## 6. Solve an extension

**Task:** include a four-byte unsigned sequence number after the length field.
- Draw new offsets.
- Update `struct` format.
- Update `HEADER_SIZE`.
- Add round-trip and truncation tests.
- Keep bounds and JSON validation.

**Answer hint:** layout `!2sBBHI` and header size 10. Your schema must decide whether the sequence number is authenticated; this toy protocol is not.

## 7. Report
Record:
- Python version.
- Hex dump and field boundaries.
- 1 successful and 5 rejected cases.
- The difference between byte lengths and Unicode string lengths.
- Three parser security invariants.
- What a network receiver must do before passing a complete buffer to this parser.

**Grading:** 4/4 correct bounds, 4/4 negative tests, 4/4 clear byte diagram, 4/4 documented limitations, 4/4 safe execution.
